# 琉璃蟻偵測演算法 · 敏感度測試台

學生的 ESP32-CAM 琉璃蟻監控專題，偵測邏輯原本寫在網頁前端的 `runAIModel()`。這個頁面把那段演算法單獨拿出來，放在 GitHub Pages 上，讓你用上傳的照片做敏感度測試。

## 功能

- **保留學生演算法**：判斷流程和原版相同，都是暗像素比例加上全畫面移動量。原版逐字保留在 [`original/student_algorithm.js`](original/student_algorithm.js)。
- **參數可調整**：暗像素閾值、比例上下限、移動量閾值和 RGB 灰階權重，預設值都跟學生原版一樣。
- **上傳圖片**：支援多選、拖放和貼上。多張圖片會依檔名排序，當成連續畫面計算移動量。
- **敏感度分析**：
  - 單參數掃描：看每張圖的判定在哪個參數值切換，畫出各判定的比例，以及準確率、偵出率和特異度。
  - 雙參數熱圖：例如「暗像素閾值 × 移動量閾值」。點任一格就會套用那組參數。
  - 兩種分析的結果都能下載 CSV，用 Excel 開啟。
- 所有運算都在瀏覽器完成，照片不會上傳。

## 參數對照

| 參數 | 學生原版常數 | 意義 |
|---|---|---|
| `darkThreshold` | `65` | 灰階低於此值算暗像素 |
| `ratioMin` | `0.015` | 暗像素比例高於此值，才可能判定有螞蟻 |
| `ratioMax` | `0.25` | 暗像素比例達到此值，判定為陰影或雜物 |
| `motionThreshold` | `1.0` | 前後兩張的平均灰階差高於此值，判定為「活動中」 |
| `wR/wG/wB` | `0.299/0.587/0.114` | 灰階權重 |

## 測試

```bash
node test/parity.test.mjs
```

這個測試會把學生原版程式放進假 DOM 執行，確認在預設參數下，`js/algorithm.js` 的判定和原版完全一致。測試資料涵蓋活動中、無位移、陰影和無螞蟻四種判定。

## 拍攝測試照片的建議

- 用 ESP32 本身拍，在網頁開 `http://192.168.4.1/capture`，每隔幾秒另存一張。檔名請依序編號。
- 鏡頭位置、解析度、補光燈狀態保持固定。學生程式在自動燈光模式下每張都會閃燈，前後兩張的亮度不同，會讓移動量偏高。
- 在表格的「人工標註」欄標出每張的真實狀態，才能算準確率。

## 本機執行

```bash
python3 -m http.server 8000
# 開啟 http://localhost:8000
```

頁面使用 ES modules，必須透過 HTTP 開啟，直接雙擊 HTML 檔案會無法載入。

## 端對端測試（Python Playwright）

```bash
pip install playwright && playwright install chromium
python test/e2e_pages.py                          # 測 GitHub Pages 上的版本
python test/e2e_pages.py http://localhost:8000/   # 測本機
```

測試流程依序是：載入示範圖組、確認預設參數下的判定、調整參數後確認判定會改變、恢復預設值、上傳檔案、單參數掃描並下載 CSV、雙參數熱圖並下載 CSV，最後截圖。截圖預設存到系統暫存目錄，可以用環境變數 `SHOT_DIR` 指定位置。

示範圖組是程式畫出來的合成畫面，只用來試操作流程。其中 `08_shadow` 是一個刻意保留的反例：陰影只佔約 18%，沒有超過學生設定的 25% 上限，所以會被誤判成「活動中」。
